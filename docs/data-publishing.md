# Публікація даних і GitHub Pages

## Узгоджене розуміння

- Код проєкту зберігається у звичайному Git-репозиторії.
- Готова база потрібна для швидкого старту без багатогодинної первинної синхронізації.
- PDF залишаються локальним кешем і завантажуються з першоджерела.
- GitHub Pages є статичною сторінкою проєкту, а не середовищем запуску FastAPI.
- Дані не містять облікових записів або приватної інформації користувачів.
- Набір даних оновлює власник проєкту після успішної синхронізації та перевірки.

## Припущення

- Репозиторій і Release є публічними.
- Поточний масштаб — сотні випусків, сотні тисяч записів і невеликий трафік.
- Допустиме ручне створення нового Release snapshot після значних оновлень.
- Кожен Release є незмінним; нове оновлення отримує новий тег.

## Розглянуті варіанти

1. **GitHub Release asset — обрано.** Не збільшує Git-історію, має стабільне посилання `latest`, підтримує великі файли.
2. Git LFS. Зручний для checkout, але кожна версія бази повторно використовує storage та bandwidth квоту.
3. База у звичайному Git. Відхилено через ліміт одного файла й постійне зростання історії.

## Decision log

| Рішення | Причина |
|---|---|
| База публікується як `litopys.db.zst` | Snapshot стискається приблизно з 576 до 91 MiB |
| Поруч публікуються SHA-256 і `dataset.json` | Дає перевірку цілісності та відтворювані метадані |
| PDF не входять до Release | Вони займають близько 693 MiB, доступні з першоджерела, а умови повторного поширення явно не зазначені |
| Pages розгортається з `docs/` через Actions | Не потребує окремого frontend build і автоматично оновлюється з `main` |
| `db-download` не перезаписує наявну базу без `--force` | Захищає локальні результати синхронізації |

## Створення snapshot

```bash
uv run litopysdb snapshot
```

Команда створює в `dist/data/`:

- `litopys.db.zst`;
- `litopys.db.zst.sha256`;
- `dataset.json`.

Для публікації створіть тег `data-YYYY-MM-DD` і GitHub Release, потім додайте всі три файли як assets.

## GitHub Pages

Workflow `.github/workflows/pages.yml` публікує каталог `docs/`. Для першого запуску в GitHub відкрийте:

1. **Settings → Pages**.
2. У **Build and deployment → Source** виберіть **GitHub Actions**.
3. Відкрийте **Actions → Deploy GitHub Pages → Run workflow** або зробіть push у `main`.

Сайт буде доступний за адресою `https://nazarb25.github.io/LitopysBooksDB/`.

## Онлайн-пошук на Render

GitHub Pages публікує тільки статичні файли. Повноцінний пошук запускається як
Docker Web Service на Render за конфігурацією `render.yaml`. База додається до
образу під час збірки командою `litopysdb db-download`, а контейнер запускає той
самий FastAPI застосунок, що й локальна команда `uv run litopysdb serve`.

Після створення нового GitHub Release виконайте в Render **Manual Deploy → Clear
build cache & deploy**. Очищення build cache потрібне, щоб шар завантаження бази
зі стабільної адреси `releases/latest` був зібраний заново.
